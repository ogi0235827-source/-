## 2. あなたの武器 ― このリポジトリの開発履歴

このリポジトリ（`index.html`）に、**検証可能な一次情報が丸ごと残っています。**

```
25ebb33  01:03  子供向けバブルポップゲームを追加            +651行
67c0fda  01:08  泡タップ→動物タッチゲームにリニューアル     +206 / -187
f646bd2  01:43  ボタン動作・アニメーション・互換性の修正     +275 / -396
05612db  02:58  完全シンプル化：確実に動くバージョンに書き直し +254 / -387
                                                    → 最終 416行
```

この履歴が語っていること:

- **約2時間**（01:03 → 02:58）で、動く子供向けゲームが1本完成している
- 途中で **企画ごと作り替えている**（バブルポップ → どうぶつタッチ）
- **コードは一度651行まで膨らみ、最後は削って416行に落として「確実に動く」状態にした**
  （最終コミットのメッセージが「完全シンプル化：確実に動くバージョンに書き直し」）

**これは、AI開発の教科書には載っていないが、実際にやると必ず起きることです。**
「AIに任せたらコードが膨張して動かなくなり、削って直した」という体験は、
記事にした瞬間に **一次情報** になります。しかも `git log` で裏が取れる。

一般論の「Claude Codeの使い方」は誰でも書ける。
**「651行まで膨らませて失敗し、416行に削って動かした2時間」は、あなたにしか書けない。**

## 3. ポジショニング

| 項目 | 設定 |
|---|---|
| **名乗り** | プログラミング未経験から、AIで「実際に動くもの」を作っている人 |
| **読者** | 「AIで何か作りたいが、何から手を付けるか分からない」非エンジニア |
| **売るもの** | 汎用ノウハウではなく **失敗を含んだ実装記録と、そこから抽出した型** |
| **競合との差** | 競合は「AIでこう書けます」。こちらは「AIでこう作って、こう失敗して、こう直した」 |
| **副業への接続** | 「稼ぐ方法」を先に売らない。**「作れる人になる」→ その先に副業がある** の順で書く |

**副業・マネタイズの扱いについて（重要）**

「AI副業で月◯万円」系は最も売れやすいが、**実績がないうちに書くと嘘になります。**
noteは信頼が資産のプラットフォームなので、ここで嘘をつくと後で全部効かなくなる。

したがって当面の方針:
- **フェーズ1（〜3ヶ月）**: 「作れるようになる」側だけを書く。副業は「作れた先にある」と示すに留める
- **フェーズ2**: note自体の販売実績が出たら、**その実数値を一次情報として**副業側を書く
  （「AI副業で稼ぐ方法」ではなく「AIで作ったものをnoteで売った記録」なら、実績ゼロからでも誠実に書ける）

## 4. コンテンツの3階層

```
【無料・週2本】 信頼の証明
  ├ 体験記録（作った / 失敗した / 直した）  ← noteのアルゴリズムが最も好む型
  └ 小さな実用（すぐ使える1個のコツ）      ← 保存・スキが付きやすい

【有料・週1本】 再現可能な「型」
  └ 無料記事で見せた体験を、読者が再現できる手順に変換したもの
    ※ 実用ノウハウ系にすると単価が約1.9倍（1,842円 vs 983円）

【マガジン / メンバーシップ】 積み上げ
  └ 有料記事が5本溜まった時点でマガジン化。以降メンバーシップへ
    ※ メンバーシップは前年比+81.3%と最も伸びている
```

**無料と有料の切り分けルール（これを守らないと売れません）**

| | 無料に置く | 有料に置く |
|---|---|---|
| 内容 | **何が起きたか**（体験・結果・失敗） | **どうやるか**（手順・プロンプト・判断基準） |
| 出し惜しみ | **しない**。無料が薄いと有料は売れない | — |
| 具体物 | スクショ・結果 | コピペで使えるもの（プロンプト全文・コード・チェックリスト） |

有料部分に「結論」を隠すのは最悪手です。結論は無料で出す。
**有料で売るのは「あなたが同じことをやるための手順と、失敗を回避する判断基準」。**

## 6. 週次の運用サイクル

| 曜日 | やること |
|---|---|
| 月 | 無料①を投稿（体験記録） |
| 木 | 無料②を投稿（小さな実用） |
| 土 | 有料①を投稿（再現手順） |

**このサイクルの生命線は日曜です。**
実際に手を動かして何かを作らないと、書くべき一次情報が枯れます。
一次情報が枯れた瞬間、記事は「AIが書いた一般論」に落ちて、売れなくなります。

→ 何を作ったかを `note/00_strategy/INTAKE.md` の「今週やったこと」に書き足してください。
   それが次週の記事3本の原料になります。

## 7. 3ヶ月のマイルストーン

| 時期 | 目標 | 判断指標 |
|---|---|---|
| 1ヶ月目 | 記事12本（無料8・有料4）を積む | 有料が **1部でも売れる** |
| 2ヶ月目 | 反応の出た型を特定して寄せる | スキ数・フォロワーの伸びが特定ジャンルに偏り始める |
| 3ヶ月目 | 有料記事をマガジン化、価格を980円へ | 有料の累計10部 |

**うまくいかない場合の切り分け**
- 読まれない → タイトルの問題（`20_templates/title-checklist.md` を再確認）
- 読まれるが売れない → 無料部分で価値を証明できていない／有料の中身が一般論
- 売れるが続かない → 一次情報の供給が止まっている（日曜のサイクルが崩れている）
