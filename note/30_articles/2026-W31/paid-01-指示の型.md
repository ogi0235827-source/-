# 非エンジニアのためのClaude Code実践ガイド：作りたいものを「動くもの」に変える指示の型

- **最初のひと言テンプレート**（コピペ可）— これを言うだけで手戻りが激減します
- **詰まったときの頼み方7パターン**（コピペ可）— 症状別に、そのまま貼れる形

## 誰向けか / 誰向けでないか

**向いている人**
- コードは書けないが、AIで何か作ってみたい人
- 一度作り始めたが、途中で動かなくなって止まっている人
- 「いい感じにして」と頼み続けて、何が起きているか分からなくなった人

**向いていない人**
- 普段からコードを書いている人
  → この記事に書いてあることは、たぶん既にご存知です。買わないでください
- Claude Code の設定方法・インストール手順を知りたい人
  → この記事は「入れた後、どう頼むか」だけを扱います
- 「AIで月◯万円稼ぐ方法」を探している人
  → 稼ぐ話は一切書いていません。**作れるようになる話だけ**です

## 前提：私が実際にやったこと

★［無料記事①のURL］で書いた通り、私は深夜1時から3時までの**約2時間**で、
子供向けのスマホゲームを1本作りました。

その過程はこうです。

```
01:03  子供向けバブルポップゲームを追加            +651行
01:08  泡タップ→動物タッチゲームにリニューアル     +206 / -187
01:43  ボタン動作・アニメーション・互換性の修正     +275 / -396
02:58  完全シンプル化：確実に動くバージョンに書き直し +254 / -387
                                            → 最終 416行
```

注目してほしいのは、**後半2回のコミットで、足した行より消した行のほうが多い**ことです。

- 3回目：275行足して **396行消した**
- 4回目：254行足して **387行消した**

コードは一度 **651行**まで膨らみ、最後は **416行**まで削られました。
**動くようになったのは、機能を足したからではなく、削ったからです。**

この記事は、その2時間で私が学んだことを、
**あなたが同じ2時間を繰り返さずに済む形**に整理したものです。

## 結論だけ先に

出し惜しみしても仕方がないので、結論はここに全部書きます。

> **1. 最初に「誰が、どの端末で使うか」を言う。**
>    私はこれを言わなかったせいで、67ヶ所を書き直す羽目になりました。
>
> **2. 「いい感じにして」と言わない。**
>    AIは頼めば頼むだけ足します。増えるほど、読めない人には手に負えなくなります。

## §1 最初のひと言テンプレート

最初の1回で、これを全部言ってください。**ここで言い忘れた条件は、後で全部やり直しになります。**

```
【作りたいもの】
（例：3歳の子供が遊べる、動物をタッチして遊ぶゲーム）

【誰が使うか】
（例：ひらがなしか読めない子供。大人が横にいない状態でも遊べること）

【どの端末で動かすか】
（例：家にある古いAndroidタブレット。Chromeで開く）

【技術的な条件】
- HTMLファイル1つで完結させてください（ファイルを分けないでください）
- 外部のライブラリは使わないでください
- 古い端末でも確実に動く書き方でお願いします
  （const / let / アロー関数を避け、var と function で書いてください）
- 画像ファイルは使わず、絵文字と CSS だけで見た目を作ってください

【最初に作ってほしい範囲】
まず「動く最小限」だけ作ってください。演出・音・エフェクトは後回しでいいです。

【禁止】
私はコードが読めません。説明は日本語で、何をしたかだけ簡潔に書いてください。
```

**各項目が効く理由**

| 項目 | 書かないとどうなるか |
|---|---|
| 誰が使うか | 大人向けのUIで作られる。子供には字が小さくて押せない |
| どの端末 | 最新環境前提のコードが出る。**私はこれで67ヶ所の書き直しが発生しました** |
| ファイル1つ | 複数ファイルに分割され、読めない人には管理不能になる |
| ライブラリなし | ネットが無いと動かなくなる。読み込み失敗で無反応になる |
| 画像を使わない | 画像の準備・配置でつまずく。絵文字なら文字なので絶対に壊れない |
| **最小限から** | ★これが一番効きます。§2で詳しく書きます |
| 説明は日本語で簡潔に | 読めない技術説明が延々と返ってきて、判断できなくなる |

**「画像を使わない」の効果**

私のゲームは、動物30種類が全部**絵文字**です。

```
🐶いぬ 🐱ねこ 🐭ねずみ 🐰うさぎ 🦊きつね 🐻くま 🐼パンダ 🐨コアラ
🐯とら 🦁らいおん 🐮うし 🐷ぶた 🐸かえる 🐵さる 🐔にわとり 🐧ペンギン
🦆あひる 🦋ちょうちょ 🐢かめ 🐬いるか 🦓しまうま 🦒きりん 🐘ぞう ...
```

画像を1枚も用意していません。だから**素材探しの時間がゼロ**で、
**画像が読み込めなくて表示されない事故も起きません。**

非エンジニアが最初に詰まるのは、たいていコードではなく**素材の準備**です。
絵文字で回避できるなら、回避したほうがいい。

## §2 なぜ「いい感じにして」が事故るのか

私の失敗の中心はこれです。順番に何が起きたか書きます。

**起きたこと**

1. 「動くもの」が5分で出てきた（651行）
2. 見た目が地味だったので「もっと楽しい感じにして」と頼んだ
3. エフェクトが足された
4. 「もっと派手に」と頼んだ
5. アニメーションが足された
6. …気づくと、**何が原因で動かないのか、自分で分からなくなっていた**

**なぜ止められなかったか**

AIは頼めば頼むだけ足してくれます。しかも、**足すたびにちゃんと動いているように見える。**
壊れるのは、いくつか足した後です。そのとき「どれが原因か」が分からない。

コードが読める人なら、直前の変更を見れば分かります。
**読めない人は、これが原理的にできません。** ここが決定的な差です。

**対策：1回の指示で1つだけ変える**

```
（悪い）もっと楽しい感じにしてください
（良い）動物が出てくるときに、ぽんと跳ねる動きを付けてください。他は変えないでください
```

「**他は変えないでください**」を毎回付ける。これだけで、壊れたときに原因が特定できます。

**さらに強い対策：動いた時点で保存する**

コードが読めなくても、これはできます。

```
いまの状態で動いています。この時点を保存しておきたいので、
git でコミットしてください。メッセージは「動作確認OK：◯◯まで」でお願いします。
```

こうしておくと、壊れたときに **「さっきのコミットに戻して」** の一言で復旧できます。
私の4つのコミットは、まさにこれをやった記録です。

**コードが読めない人にとって、コミットは唯一の安全網です。**
読めない以上、壊れたものを読んで直すことはできない。**戻る以外に方法がありません。**

## §3 詰まったときの頼み方7パターン

症状別に、そのまま貼れる形で置いておきます。

### パターン1：ボタンを押しても何も起きない

```
ボタンを押しても反応しません。
HTMLに直接書かれた onclick="..." を、JavaScript側から繋ぐ形に変えてください。
機能は変えないでください。
```

### パターン2：自分のPCでは動くのに、他の端末で動かない

```
このコードを、古い端末でも確実に動くように直してください。
機能は変えず、以下だけ直してください。
1. const / let を var に、アロー関数 (=>) を function に
2. el.remove() を if (el.parentNode) el.parentNode.removeChild(el) に
書き換えた箇所が何ヶ所あったかも教えてください。
```

最後の1行が重要です。**数字が返ってくることで、どれだけ地雷があったかが分かります。**
私は67ヶ所（`const`/`let` が54、アロー関数が13）でした。

### パターン3：動かなくなったが、原因が分からない

```
動かなくなりました。私はコードが読めないので、原因を推測して直すのではなく、
まず「何が起きているか」だけを日本語で説明してください。
勝手に修正しないでください。
```

**「勝手に修正しないでください」が効きます。**
これを言わないと、推測で直され、直っていない上にコードだけ増えます。

### パターン4：コードが増えすぎて手に負えない

```
コードが増えすぎて、私には管理できなくなりました。
いま動いている機能は保ったまま、コードを短くシンプルに書き直してください。
削って構いません。何を削ったか、リストで教えてください。
```

私が最後にやったのがこれです。**254行足して387行消えました。**

### パターン5：一部の機能だけ捨てたい

```
◯◯の機能を丸ごと削除してください。
関連するコードも全部消してください。残骸を残さないでください。
```

「**残骸を残さないでください**」を付けないと、使われないコードが残ります。
これが後でじわじわ効いてきます。

### パターン6：音が鳴らない / 鳴らなくてもいい

```
音が鳴らない端末があります。
音が鳴らなくてもゲームが止まらないようにしてください。
```

私のコードでは、音の処理が丸ごと `try { } catch(e) { }` で囲まれています。
**鳴らせなかったら黙って諦めて、ゲームは進む**という作りです。

子供向けだと特にこれが効きます。音が出ないだけで全部止まるのが最悪だからです。

### パターン7：作り直したくなった

```
方向性を変えます。いまのコードは捨てて構いません。
◯◯ではなく△△を作りたいです。ゼロから作り直してください。
```

**遠慮しなくていいです。** 私は作り始めて5分後に企画ごと変えました。
泡をタップするゲームを、動物をタッチするゲームに丸ごと変えています（`+206 / -187`）。

これは §4 の話につながります。

## §4 「増やす / 削る」の判断基準

| 状況 | 判断 | 実際の頼み方 |
|---|---|---|
| まだ動いていない | **増やさない**。動くまで機能を足さない | 「まず動く最小限だけ」 |
| 動いた直後 | **保存する**。増やす前にコミット | 「この時点でコミットして」 |
| 動いていて、物足りない | 1つだけ足す | 「◯◯だけ追加。他は変えないで」 |
| 足したら壊れた | **戻す**。直そうとしない | 「さっきのコミットに戻して」 |
| 何度も壊れる | **削る**。機能が多すぎる | 「動く状態を保ったまま短く」 |
| 方向性が違う | **捨てる**。早いほど傷が浅い | 「ゼロから作り直して」 |

**「捨てる」の判断について**

これが今回いちばん実感したことです。

私は作り始めて **5分後**に企画ごと捨てました。自分で書いていたら、絶対にできなかった判断です。
1時間かけて書いたコードを5分後に捨てるのは、人間には無理です。

**5分で作れたから、5分で捨てられた。**

これはAIで作ることの一番大きな利点だと思っています。
速く作れることより、**速く捨てられること**のほうが効く。

だから、**方向性が違うと感じたら、その日のうちに捨ててください。**
「せっかく作ったから」で残したものは、最後まで足を引っ張ります。

## §5 私がハマった4つの落とし穴と復旧手順

### 落とし穴1：ボタンがHTMLに直接繋がれていた

**症状**：押しても無反応。エラーも出ない。
**原因**：`onclick="startGame()"` という書き方が、関数がグローバルに公開されている前提だった。
**復旧**：§3 パターン1
**予防**：最初のひと言で「ボタンはJavaScript側から繋いでください」と言う

### 落とし穴2：新しい書き方が古い端末で動かなかった（67ヶ所）

**症状**：自分のPCでは完璧。渡した端末では画面が真っ白か、無反応。
**原因**：`const` / `let` が54ヶ所、アロー関数が13ヶ所。
**復旧**：§3 パターン2
**予防**：**最初に端末を言う。これだけで67ヶ所が丸ごと消えます**

これが一番もったいなかった失敗です。**ひと言で防げた作業に、かなりの時間を使いました。**

### 落とし穴3：要素の消し方でエラーが出ていた

**症状**：しばらく遊んでいると止まる。最初は動く。
**原因**：`el.remove()` が古い環境で動かない、かつ、すでに消えた要素をもう一度消そうとしていた。
**復旧**：

```javascript
if (el.parentNode) el.parentNode.removeChild(el);
```

**予防**：アニメーションで要素が出たり消えたりする作りなら、最初から上の形で頼む

**「最初は動くが、しばらくすると止まる」は、この型の症状であることが多い**と覚えておくと当たります。

### 落とし穴4：コードが651行まで膨らんで、手に負えなくなった

**症状**：どこを直せばいいのか、自分で判断できなくなった。
**原因**：「いい感じにして」を繰り返した。
**復旧**：§3 パターン4。私はこれで **416行**まで落としました。
**予防**：1回の指示で1つだけ変える。動いたら毎回コミットする。

**コードが読めない人にとって、行数はそのまま「手に負えなさ」です。**
短く保つことが、そのまま作り切れるかどうかを決めます。

## よくある質問

**Q. コードが全く読めなくても大丈夫ですか？**
A. 私も読めません。ただし **「戻る」ができる状態は必ず作ってください**（§2のコミット）。
読めない人は壊れたものを直せないので、戻る以外の手段がありません。

**Q. 2時間で本当にできますか？**
A. 私の場合はできました。ただし **1時間15分は削る作業**です。
「2時間で完成」ではなく「**1時間で膨らませて、1時間で削る**」と思っておくほうが実態に近いです。

**Q. もっと大きなものは作れますか？**
A. この記事の範囲は「HTMLファイル1つで完結するもの」です。
それを超える規模は、私自身がまだやっていないので書けません。やったら書きます。

**Q. AIが書いたコードを公開・配布していいですか？**
A. 私はこのゲームを自分の子供に使わせているだけです。
配布・販売については使うツールの利用規約を確認してください。ここでは断定できません。
