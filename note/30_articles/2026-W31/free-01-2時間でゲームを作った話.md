# プログラミング未経験の私が、Claude Codeで子供向けゲームを2時間で作った話

## 何をしたか

- **いつ**：ある日の深夜1時から3時まで
- **何を**：子供向けのスマホゲームを1本
- **結果**：416行のHTMLファイル1つで、ちゃんと動くものができた

コミットの時刻がそのまま残っているので、正確に書けます。

```
01:03  子供向けバブルポップゲームを追加
01:08  泡タップ→動物タッチゲームにリニューアル
01:43  ボタン動作・アニメーション・互換性の修正
02:58  完全シンプル化：確実に動くバージョンに書き直し
```

**1時間55分**です。うち最後の1時間15分は、**増やす作業ではなく減らす作業**でした。
そこが一番書きたいところなので、最後まで読んでもらえたら嬉しいです。

## きっかけ

［要確認3：実際の動機に置き換えてください］

子供に何か作ってやりたかった、というのが出発点でした。
ただ私はコードが書けません。書けないのに「作れるらしい」という話だけは聞いていて、
半信半疑のまま Claude Code を開いた、というのが正直なところです。

## 実際にやったこと

### 01:03 — 5分で「動くもの」が出てきた

最初に頼んだのはバブルポップでした。泡が浮かんできてタップすると割れる、あれです。

出てきたのは **651行のHTMLファイル1つ**。ブラウザで開いたら、動きました。

正直、ここで一回びっくりしています。5分です。

### 01:08 — 5分後に、企画ごと作り替えた

ところが、画面を見て思いました。**泡、地味だな**と。

子供が喜ぶかというと、たぶん喜ばない。もっと分かりやすく「うわっ」となるものがいい。
それで、泡を全部やめて **動物の絵文字が飛び出してくる**ゲームに変えました。

`+206行 / -187行`。ほぼ半分書き換わっています。

自分で書いていたら、この判断は絶対にできなかったと思います。
1時間かけて作った泡を、5分後に捨てる決断はできない。
**5分で作れたから、5分で捨てられた。** ここは今回いちばん実感したことでした。

最終的に、動物は30種類入っています。

```
🐶いぬ 🐱ねこ 🐭ねずみ 🐰うさぎ 🦊きつね 🐻くま 🐼パンダ 🐨コアラ
🐯とら 🦁らいおん 🐮うし 🐷ぶた 🐸かえる 🐵さる 🐔にわとり 🐧ペンギン ...
```

全部ひらがなで名前が出るようにしました。まだ漢字が読めなくても遊べるように。

### 01:43 — ここから「動かない」との戦いが始まる

ここで問題が起きます。**自分のPCでは動くのに、渡した端末で動かない。**

原因は3つありました。

**1つめ：ボタンが反応しない**

最初のコードは、HTMLのボタンにこう書かれていました。

```html
<button onclick="startGame()">あそぶ！🎉</button>
```

一見ちゃんとしてそうに見えます。でもこれは、`startGame` という関数が
「グローバルに公開されている」ことが前提の書き方です。条件が揃わないと、押しても無反応になる。

最終的にはJavaScript側から直接くっつける形に変えました。

```javascript
byId('btn-start').onclick = startGame;
byId('btn-retry').onclick = startGame;
byId('btn-home').onclick  = showTitle;
```

**2つめ：新しい書き方が、古い端末で動かない**

これが一番効きました。AIが最初に書いてくれたコードには、
モダンなJavaScriptの書き方が入っていました。`const` `let` や、`=>` のアロー関数です。

数えたらこうでした。

| | 修正前 | 修正後 |
|---|---|---|
| `const` / `let` | **54ヶ所** | **0ヶ所** |
| アロー関数 `=>` | **13ヶ所** | **0ヶ所** |

全部、古い書き方（`var` と `function`）に書き直しました。
新しい書き方が悪いわけではありません。**古い端末で確実に動かしたいなら、古い書き方のほうが安全**という、それだけの話です。

うちの場合、遊ぶのは最新のスマホではなく、家に転がっている古いタブレットでした。
**「誰が、どの端末で遊ぶのか」を最初に言っていれば、この1回は丸ごと不要だった**と思います。

**3つめ：要素の消し方**

`el.remove()` という書き方も、古い環境だと効かないことがあります。

```javascript
// 修正前
el.remove();

// 修正後
if (el.parentNode) el.parentNode.removeChild(el);
```

長くて格好悪いですが、こちらは確実に動きます。

### 02:58 — 651行を416行に削って、やっと落ち着いた

ここまでで、コードはどんどん増えていました。
直すたびに足され、機能を足すたびにまた足され。

最後のコミットで、**254行足して387行消しました。** 差し引き133行減っています。
651行まで膨らんだものが、最終的に **416行**。

コミットメッセージは自分でこう書いていました。

> 完全シンプル化：確実に動くバージョンに書き直し

**動くようになったのは、機能を足したからではなく、削ったからでした。**

## 失敗したこと

いちばんの失敗は、**「いい感じに動くようにして」と言い続けたこと**です。

AIは頼めば頼むだけ足してくれます。エフェクトも、アニメーションも、演出も。
気持ちよく増えていって、気づいたら **何が原因で動かないのか自分で分からなくなっていました。**

コードが読めないので、増えれば増えるほど手に負えなくなる。
これは書ける人より、書けない人のほうが深く刺さる罠だと思います。

もうひとつは、**遊ぶ端末を最初に伝えなかったこと。**
54ヶ所の書き直しは、最初のひと言で消せた作業でした。

## どう解決したか

**「作って」ではなく「削って」と頼んだ**ことです。

具体的には、「動く状態を保ったまま、機能を減らしてシンプルにしてほしい」と伝えました。
そこから出てきたのが、いまの416行です。

作るのを手伝ってもらうのと同じくらい、**捨てるのを手伝ってもらう**のが効きました。

## 分かったこと

1. **5分で作れると、5分で捨てられる。** 企画を作り替える判断が、驚くほど軽くなる
2. **動かない原因の多くは「環境の違い」。** 誰がどの端末で使うかを最初に言う
3. **足すより削るほうが効く。** コードが増えるほど、書けない人には手に負えなくなる

## いま動いているもの

最終的にこうなりました。

- 60秒で、飛び出してくる動物をタッチして点を取る
- **小さい動物ほど高得点**（子供が自然と難しいほうを狙うようになる）
- 続けてタッチするとコンボ
- ハイスコアは端末に保存されるので、次に開くと前回の記録が出る
- 音が鳴る（ただし端末の設定によっては鳴らないので、鳴らなくても止まらないようにしてある）

全部で **HTMLファイル1つ、416行**。ダブルクリックで開けば動きます。
