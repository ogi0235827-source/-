# AIが書いたコードが動かないとき、最初に確認する3ヶ所

## 結論

自分のPCでは動くのに、他の端末で動かない。
コードが読めなくても、**この3ヶ所をAIに聞くだけで**だいたい片付きます。

1. **ボタンの繋ぎ方**（`onclick="..."` がHTML側に直接書かれていないか）
2. **新しい書き方**（`const` `let` `=>` が入っていないか）
3. **要素の消し方**（`.remove()` が使われていないか）

そのままコピペできる頼み方は、この記事の最後に置いておきます。

## なぜこれが効くのか

AIは基本的に、**いま一番新しくて綺麗な書き方**でコードを出してきます。
それ自体は正しい。ただ、**あなたが実際に動かしたい端末が古い場合、そこが全部そのまま地雷になります。**

しかもこの手のエラーは、**エラーメッセージが出ないまま、ただ無反応になる**ことが多い。
書ける人なら開発者ツールを開けば分かりますが、書けない人には「なぜか動かない」としか見えません。

だから、**原因を探すより先に、地雷になりやすい3ヶ所を潰す**ほうが早いです。

## ① ボタンの繋ぎ方

**探すもの**：HTMLの中に、こういう書き方があるか。

```html
<button onclick="startGame()">あそぶ！</button>
```

これは「`startGame` という関数が、どこからでも呼べる状態になっている」前提の書き方です。
条件が揃わないと、押しても**何も起きません**。エラーも出ません。

**直した形**：JavaScript側から繋ぎ直します。

```javascript
byId('btn-start').onclick = startGame;
byId('btn-retry').onclick = startGame;
byId('btn-home').onclick  = showTitle;
```

私の場合、これでボタンが反応するようになりました。

## ② 新しい書き方

**探すもの**：`const` `let` `=>`（矢印）の3つ。

私が実際に作った子供向けゲームでは、こうなっていました。

| | 修正前 | 修正後 |
|---|---|---|
| `const` / `let` | **54ヶ所** | **0ヶ所** |
| アロー関数 `=>` | **13ヶ所** | **0ヶ所** |

**67ヶ所**です。これを全部、古い書き方（`var` と `function`）に直したら動きました。

誤解のないように書いておくと、**新しい書き方が悪いわけではありません。**
むしろ普通は新しいほうがいい。ただ、**古い端末で確実に動かしたいときだけは、古い書き方のほうが安全**という話です。

家に転がっている古いタブレットで子供に遊ばせる、みたいな用途だと、これがそのまま効きます。

## ③ 要素の消し方

**探すもの**：`.remove()`

```javascript
// 危ない
el.remove();

// 安全
if (el.parentNode) el.parentNode.removeChild(el);
```

下は長くて格好悪いですが、確実に動きます。

`if (el.parentNode)` が付いているのも意味があって、
**すでに消えているものをもう一度消そうとしてエラーになる**のを防いでいます。
アニメーションが終わったタイミングで消す、みたいな処理だと普通に起きます。

## そのまま使える頼み方

3ヶ所を自分で探す必要はありません。これをコピペしてください。

```
このコードを、古い端末でも確実に動くように直してください。
機能は変えず、以下の3点だけ直してください。

1. HTMLに直接書かれた onclick="..." を、JavaScript側から繋ぐ形に変える
2. const / let を var に、アロー関数 (=>) を function に書き換える
3. 要素の削除を el.remove() ではなく
   if (el.parentNode) el.parentNode.removeChild(el) の形にする

書き換えた箇所が何ヶ所あったかも教えてください。
```

最後の1行を入れておくと、**どれだけ地雷があったかが数字で分かります。**
私の場合は67ヶ所でした。

## やりがちな間違い

**「動かない」とだけ伝えること。**

これをやると、AIは原因を推測して、あちこち直そうとします。
結果、直っていない上にコードだけ増えて、余計に分からなくなります。

**「どこを、どう直すか」を指定して頼むほうが、圧倒的に速い。**
コードが読めなくても、直す場所さえ指定できれば作業は進みます。

## そもそも、これを起こさない方法

一番効くのは、**最初のひと言で環境を伝えること**です。

```
古いAndroidタブレットで動かします。
新しいJavaScriptの書き方は避けて、古い端末でも確実に動く書き方でお願いします。
```

これを最初に言っておけば、67ヶ所の書き直しは丸ごと発生しませんでした。

**AIは、言われていない条件は考慮しません。**
「誰が、どの端末で使うのか」は、作りたいものの説明と同じくらい先に言ったほうがいいです。
