# 無料記事テンプレート

**目的**: 集客ではなく **信頼の証明**。「この人は実際にやっている」を示す。
**分量**: 2,000〜3,500字
**投稿**: 月曜（体験記録型）/ 木曜（小さな実用型）

> 無料記事で出し惜しみすると、有料は売れません。
> 無料で「結論」まで出し切って、有料では「再現手順」を売る。

---

## 型A：体験記録型（月曜）

noteのアルゴリズムが最も好む型。一次情報そのもの。

```markdown
# [タイトル：具体的な数字を入れる]

## 何をしたか（3行）
- いつ：
- 何を：
- 結果：

## きっかけ
なぜやろうと思ったか。読者と同じ地点に立っていたことを示す。
※ ここで「私も分からなかった」を隠さない。これが共感の入り口になる。

## 実際にやったこと（時系列）
起きたことを順番に。うまくいったことより **詰まったところを厚く**。
- スクリーンショット / コード / 実際の出力を貼る（証拠になる）

## 失敗したこと
★ここが一番読まれる。
何がどう失敗したか、そのとき何を考えたかを具体的に。

## どう解決したか
結論はここで出し切る。出し惜しみしない。

## 分かったこと（3つまで）
1.
2.
3.

## 次にやること
次回予告 = 次の記事への導線。

---
（有料記事がある場合のみ）
この失敗を回避する具体的な手順は、こちらにまとめました → [有料記事リンク]
```

## 型B：小さな実用型（木曜）

「すぐ使える1個」だけを渡す。保存・スキが付きやすい。

```markdown
# [タイトル：〜する方法 / 〜が一発で直る]

## 結論（最初に書く）
やることを1〜3行で。ここだけ読めば実行できる状態にする。

## なぜこれが効くのか
理屈を短く。読者が応用できるようになる。

## 実際の手順
1.
2.
3.
※ コピペできるものはコードブロックに入れる

## やりがちな間違い
自分が実際にハマったものだけ書く。想像で書かない。

## 補足
```

## 共通ルール

| 項目 | ルール |
|---|---|
| 冒頭3行 | ここで読むか離脱するかが決まる。結論か、意外な事実から入る |
| 一人称 | 統一する（「私」推奨） |
| 断定 | 実際に確認したことだけ断定する。推測は「たぶん」と書く |
| 数字 | 覚えている限り具体的に。曖昧なら「約」を付ける |
| 見出し画像 | 2:1。Canva連携で作れる |
| ハッシュタグ | 3〜5個。ジャンルの主要タグを外さない |

## 投稿前チェック

- [ ] `title-checklist.md` の3条件を満たしている
- [ ] 一次情報（自分が実際にやったこと）が入っている
- [ ] 結論を有料部分に隠していない
- [ ] 実績を盛っていない・嘘を書いていない
- [ ] 個人情報（家族・勤務先・居住地）が写り込んでいない
